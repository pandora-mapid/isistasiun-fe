## Project state

This started as a bare `create-next-app` scaffold and now implements **Isi Stasiun**, a 5-screen WebGIS proposal UI (Beranda `/`, Peta `/peta`, Insight `/insight`, Metodologi `/metodologi`, Rekomendasi `/rekomendasi`), recreated from a Claude Design hi-fi mockup (`Isi Stasiun Hifi v2.dc.html`, pulled via the design-system sync tool from the "Proposal Aplikasi Pemetaan Stasiun" project). Peta is a fully interactive MapLibre map over mock data (ROADMAP Fase 0 and Fase 1 are both done); the other four screens are still static mockups.

- `components/NavBar.tsx` — a single `NavBar` (bordered row) used identically on all 5 screens, including Peta; it hardcodes the 5 routes and highlights the active one via an `active` prop — no `usePathname()`. Internally split into `Brand` (the "IS" mark) and `NavLinks` (the route pills), but those two are not exported — everything renders through `NavBar`. An earlier `FloatingNavBar` variant (a glass pill overlaid on the Peta map) was removed in favor of this single component so all 5 screens look consistent; don't reintroduce a second nav variant without checking with the user first.
- `components/PetaScreen.tsx` — the only client component (`"use client"`); owns all of Peta's interactive state (tab, layers panel, category/catchment/slot filters, selected point, transparency modal, copilot reveal) and loads the data once via `usePetaData`. Its `page-canvas` is a column flexbox pinned to `100vh` (`NavBar` on top, the map `flex: 1` below) so the map always fills the remaining viewport with no page-level scroll. The illustrative basemap SVG that used to live here was replaced by `MapCanvas`; the floating panels still sit over it, absolutely positioned. **Every figure in the brief panel now comes from the mock analytics** through `lib/analytics/select.ts` — nothing in the JSX computes a number of its own, so the map and the panel cannot disagree. The one canned area left is the "Tanya Data" (copilot) tab, which is Fase 3.6.
  - **Every interactive control in the panels is a real `<button>`.** They were all `<div onClick>` at first — indistinguishable on screen, and unreachable by Tab or Enter, which made `/peta` unusable without a mouse. They keep their original look through `.btn-reset` (see the design-tokens note below) and carry `aria-pressed`/`aria-expanded`. Don't convert them back to `div`s for styling convenience; `tests/peta.spec.ts` drives three of them from the keyboard. Layer rows with no data use `aria-disabled`, not `disabled`, so the "belum ada data" tag stays readable — Playwright refuses to click them, which is the correct signal.
  - Selected point is stored as `number | null | undefined`: `undefined` means "user hasn't chosen", which falls back to the biggest-gap point; `null` means the user explicitly cleared it. Collapsing those two into one value makes the close button impossible to implement — the default would instantly refill it.
  - Three layer rows are live; only *Indeks sewa* and *Event* are disabled with a "belum ada data" tag, and they genuinely have no mock data. `LAYER_GROUPS` in `lib/map/config.ts` decides which rows are live — add a key there and the row activates itself. Do not mark a row "belum ada data" without checking the mock first: *Kategori hilang* and *Arus pintu* carried that tag for a while although `by_category` and `variables.F` had existed since Fase 1.
  - A *Potensi belanja* ring layer used to exist and was removed: it drew potensi and gap on two independent radius scales, so the spacing between ring and circle — the thing it was meant to communicate — varied between points whose real ratio was identical. Don't reinstate it without a zero-anchored, area-proportional scale shared with the gap circle.
  - The legend deliberately omits *Sampel tipis* even though the map still draws those points differently (white fill, grey ring). That is a team decision — the brief panel states "Tidak diestimasi" with its reason — and it is a knowing exception to the rule that every map symbol earns a legend entry. Don't "fix" it back without asking. The rendering itself must stay: without it a point with no data reads as the smallest gap, which is the opposite of the truth.
  - A *Kategori hilang* badge layer was also tried and removed. The brief panel already lists the categories by name with demand share and store count, and each row filters the map — a bare count on the map was strictly less informative. Before drawing anything on the map that the panel already explains, check whether the map version can carry the same meaning; usually it cannot.
- `components/ImagePlaceholder.tsx` — stands in for real station/survey photography.
- All 5 pages are laid out inside `.page-canvas` (defined in `globals.css`), now fluid at `width: 100%` though authored at 1440px. Internal layouts still use fixed grid columns, so anything under ~1100px breaks — responsiveness is a proposal promise that remains unbuilt (`ROADMAP.md` §6).
- `.btn-reset` in `globals.css` strips the browser's default button chrome (`all: unset`) so a `<button>` can wear `.lyr`, `.chip`, `.pill`, `.row`, or `.ic` and look exactly like the `div` it replaced, plus a `:focus-visible` ring. **It must stay above those rules in the file.** They are all single-class selectors, so the later one wins — move `.btn-reset` below them and its `all: unset` deletes the very styling it exists to preserve, silently.
- Design tokens (the neutral/accent color scale, `.b`/`.bp`/`.bs`/`.bw` buttons, `.chip`, `.pill`, `.glass`, `.k`/`.cap` labels, `.row`, `.lyr`, `.dot`, `.mono`) are ported 1:1 from the source `.dc.html` into `globals.css` — most inline styles in the pages use literal hex/px values matching that source rather than Tailwind utility classes or the `:root` custom properties, so a rebrand means editing values across all 5 files, not just `:root`. Always reference the font via `var(--font-inter)`, never a literal `'Inter'` string — next/font hashes the actual generated font-family name, so a literal string silently falls back to the system font.
- Several buttons across the app are intentionally inert (styled, no `onClick`) because they'd need a real backend: PDF/brief export, "Bandingkan", "Tabel atribut". This is expected, not a bug to fix reflexively — confirm with the user before wiring them to anything.

Note the `@AGENTS.md` import above: `AGENTS.md` is auto-generated and rewritten by `next dev` itself (see `node_modules/next/dist/server/lib/generate-agent-files.js`). It warns that this Next.js version (16.3.2) has breaking API/convention changes relative to older training data, and points to `node_modules/next/dist/docs/` as the authoritative reference — check there before assuming App Router behavior from prior knowledge. If it reappears as an uncommitted diff after `next dev` runs, that's expected; commit it to keep the tree clean rather than deleting it.

## Commands

Run from `fe/` (the actual project root — the repo lives at `D:\Lomba\MAPID\fe`, not the outer `D:\Lomba\MAPID`):

```bash
npm run dev        # start dev server (http://localhost:3000)
npm run build      # production build
npm run start      # serve the production build
npm run lint       # ESLint (flat config, eslint.config.mjs)
npm test           # Playwright: pure-logic + style-spec + browser smoke tests (59)
npm run test:style # just the fast, browser-free layer validation
```

`predev`/`prebuild` run `scripts/copy-maplibre-worker.mjs` automatically — see the MapLibre worker note under Architecture.

**Testing** is Playwright (`tests/`, config in `playwright.config.ts`), added because three separate map bugs each produced a blank map with *no error message at all* and sailed past both typecheck and lint:

- `tests/select.spec.ts` — `lib/analytics/select.ts`, the file that decides *which number* every panel and every circle shows. No browser, no React, no MapLibre — it's all pure functions, so it's the cheapest thing in the repo to test and the most expensive to get wrong: a mistake here surfaces as a **wrong number in two places at once**, not as a broken page, so neither the style validator nor a screenshot would catch it. Locks in the rules that are easy to "simplify" away: a missing category falls back to the slot aggregate (not to zero), a missing slot reads "tidak diestimasi" (not Rp 0), thin samples never shift the scale, and `domainOf` always returns a domain with width.
- `tests/scale.spec.ts` — the distance scale bar arithmetic (`lib/map/scale.ts` + `jarak()`). Also browser-free. The old hardcoded "0 150 300 m" bar never *looked* wrong, it was only ever *numerically* wrong — a class of bug no visual test can see.
- `tests/map-style.spec.ts` — validates every layer spec against MapLibre's official validator. No browser, ~1s. Catches illegal expressions (e.g. `feature-state` inside `filter`, `["zoom"]` nested inside `case`).
- `tests/peta.spec.ts` — real Chromium. Asserts features are actually **rendered** (`queryRenderedFeatures`), not merely that the page loaded, and that each Fase 1 interaction changes what is drawn or written — slot and category filters change the attached values, clicking a point sets `terpilih`, layer rows flip `visibility`, and the legend's upper bound moves with the data. Both of the bugs described in the Architecture notes above were caught here and nowhere else.
  - Three of its tests drive the panels **from the keyboard** (focus + Enter + Esc) rather than by clicking, because that is the only way the `<div onClick>` regression would ever show up — a mouse click works fine either way.
  - When a test needs to click a point, remember `map.project()` returns **canvas-relative** coordinates while `page.mouse` takes **viewport** coordinates, and the canvas sits below the NavBar — add the canvas `getBoundingClientRect()` offset, and skip points that fall under the floating panels, which would otherwise swallow the click.

Playwright reuses an already-running dev server, and starts one if there isn't one.

## Architecture

- **Next.js 16 App Router** (`app/` directory), React 19, TypeScript (strict mode).
- **Styling**: Tailwind CSS v4, configured via CSS (`@import "tailwindcss"` in `app/globals.css`) rather than a `tailwind.config.js` — there isn't one in v4's default setup. `globals.css` also carries the design tokens and shared component classes described above.
- **Path alias**: `@/*` maps to the project root (`./*`) per `tsconfig.json`.
- **Fonts**: Inter (weights 400–900) loaded via `next/font/google` in `app/layout.tsx`, exposed as `--font-inter`.
- **Linting**: flat ESLint config (`eslint.config.mjs`) extending `eslint-config-next`'s `core-web-vitals` and `typescript` rule sets.
- **The map** (`/peta`): MapLibre GL JS v6, wired up in `components/MapCanvas.tsx`. Three conventions there are load-bearing and each one, when broken, yields a blank map with **no error message**:
  - **Every scale expression must survive a zero-width domain.** With the scale now derived from live data (`domainOf`), filtering to one category can leave a single estimated point, making `min === max`. `interpolate` requires strictly ascending inputs, so `amankanDomain()` in `style.ts` widens it — without that, every point disappears with no error. `tests/map-style.spec.ts` validates all three point layers against a deliberately flat domain.
  - **`feature-state` is legal in `paint`, illegal in `filter` *and in every layout property*.** `text-field` is layout, so a label can never read a number pushed through `setFeatureState`. Anything that must be *written out as text* travels instead as a feature **property** on the separate `point-label-values` GeoJSON source, which `PetaScreen` rebuilds whenever the slot or category changes (it holds one feature per observation point, so rebuilding is cheap).
- **A symbol layer added later wins collision placement over one added earlier.** MapLibre places symbols in reverse layer order. Putting `point-arus` after `point-label` made *every* point name vanish with no error at all. `LAYER_ORDER` therefore lists `pointArus` *before* `pointLabel`, so the supplementary number yields and the name survives; `tests/peta.spec.ts` locks that in.
- **`feature-state` is legal in `paint`, illegal in `filter`.** Analytics numbers reach the map via `setFeatureState`, so anything driven by them (gap colour/size, thin-sample styling) must be a paint expression. This is why thin-sample points share one layer with the rest and are distinguished by colour rather than filtered into their own layer.
  - **`["zoom"]` may only be the input to a top-level `interpolate`/`step`** — never nested inside `case`. Hence `circleRadiusExpression()` puts the zoom interpolation outermost and the thin-sample `case` inside it.
  - **MapLibre v6 ships its worker as a separate file** and derives its URL from `import.meta.url`. Under Turbopack that isn't an `http(s):` URL, so MapLibre falls back to `new Worker("")` — a worker pointing at the *page*, which silently does nothing: no tiles requested, no GeoJSON parsed. Fixed by `setWorkerUrl()` at module scope in `MapCanvas.tsx`, pointing at a copy that `scripts/copy-maplibre-worker.mjs` places in `public/maplibre/` (gitignored, regenerated on `predev`/`prebuild`). Don't hand-edit that folder.
- **Camera controls**: the basemap is OpenFreeMap **Liberty**, chosen because it shows the neighbourhood POIs that are this project's actual subject and because its `building-3d` layer extrudes buildings when the map is tilted. `?basemap=positron|voyager|bright` overrides it for comparison (`resolveBasemapUrl()`), and `tests/basemap-compare.visual.spec.ts` renders all four side by side. Tilt/rotate is MapLibre's own drag plus the compass, capped at `CAMERA.maxPitch` (60°) so the view can never end up staring at the horizon. **There are no custom map controls** — `visualizePitch: true` makes MapLibre call `resetNorthPitch()` on compass click instead of `resetNorth()`, which zeroes bearing *and* pitch without moving the centre, so a hand-rolled "flatten to 2D" button was redundant and was removed. An earlier auto-rotating "sweep" mode was also removed at the user's request; don't reintroduce either without asking.
- **Symbol layers must set `text-font` explicitly.** MapLibre defaults to `Open Sans Regular`, which OpenFreeMap does not serve — the glyph request 404s and every label vanishes with no error beyond an anonymous console line. `LABEL_FONT` in `lib/map/style.ts` pins `Noto Sans Regular`, which both OpenFreeMap and CARTO provide. Re-check this if the basemap changes again. `tests/peta.spec.ts` now fails on any 4xx/5xx response precisely to catch this class of silent breakage — note a 404 is *not* a `requestfailed`, so listening only for that misses it.
- **Map styling lives in exactly one file**, `lib/map/style.ts` — colours, radii, opacity, layer specs. `ROADMAP.md` §1 requires visuals be changeable without touching data/logic, so don't inline colour or size values in `MapCanvas.tsx`.
- **Data access goes through `lib/data/source.ts`**, which currently reads mock files from `public/mock/` (generated, committed). Phase 2 swaps that one file for the Go API; nothing else should need to change. Shapes are in `lib/data/types.ts` and mirror `DATA_CONTRACT.md`. Note `MapCanvas` already joins geometry to analytics via `setFeatureState` even though both come from mocks — deliberately, so the Phase 2 switch to vector tiles doesn't require rewriting style expressions.
- **Nothing may derive facts from the full feature list.** `points.features` is available today only because geometry still arrives as GeoJSON; once it becomes vector tiles the browser only holds whatever is on screen. Three things used to be computed from it and were deliberately moved:
  - point labels → `loadEntrances()` (`public/mock/entrances.json`, later `GET /stations/:id/entrances`)
  - station names → `loadStations()`
  - the opening viewport → `STUDY_BOUNDS` in `lib/map/config.ts`

  Reintroducing a `points.features` loop would compile, pass tests, and then fail in Phase 2 with a misleading symptom: the map opens somewhere random and panels show `#24` instead of "Pintu 4". See `ROADMAP.md` §4.1.
- **Configuration comes from `NEXT_PUBLIC_*` env vars, referenced literally.** `NEXT_PUBLIC_API_BASE_URL` (falls back to `/mock`) and `NEXT_PUBLIC_BASEMAP_URL` (falls back to OpenFreeMap Liberty), documented in `.env.example` — which needs the `!.env.example` negation in `.gitignore` to survive the blanket `.env*` rule. Next.js inlines these by *textual* match at build time, so they must be written as `process.env.NEXT_PUBLIC_FOO` in full; routing them through a variable yields `undefined`.
- **The basemap is served through a backend proxy** so the MAPID key never reaches the browser, but `resolveBasemapUrl()` keeps a direct fallback on purpose: if the only address were the proxy, `/peta` would die whenever the backend is down, breaking `ROADMAP.md` §9's first principle. The proxy must rewrite `glyphs`, `sprite`, and `sources.*.tiles` inside `style.json` — those carry the key, and forwarding the file unchanged yields a blank basemap. `MapCanvas` now surfaces exactly that case: `sumberDayaGagal()` reads `status` and `url` off MapLibre's `AJAXError` and shows a one-time notice naming the HTTP status and host. **The timeout path alone was not enough** — it only fires when `style.load` never arrives, whereas an unrewritten `style.json` loads perfectly and then 401s on every tile, so the failure that is most likely in production was the one failure nothing reported.
  - MAPID's `basic` style ("Street Mapid") has been loaded and verified: it serves `Noto Sans Regular`, has a `building-3d` layer, and shows the same neighbourhood POIs as Liberty. That is not a coincidence — **it is derived from OSM Liberty**, so switching between them barely changes the picture.
  - It also pulls from two hosts that are neither MAPID nor ours: the sprite from `maputnik.github.io/osm-liberty` and low-zoom relief from `klokantech.github.io`. Neither carries a key, so both work unproxied — but proxying `basemap.mapid.io` alone will not capture them, and the POI icons depend on a GitHub Pages URL nobody on this project controls.
  - `mapid` is deliberately absent from `BASEMAP_CHOICES` (that file is committed and the URL carries a key); `basemapChoiceUrl()` resolves it from the env var instead, so `?basemap=mapid` only works when `.env.local` is filled in.
- **`/peta` must never sit behind a login.** `lib/data/source.ts` has a `setAuthToken()` seam that attaches `Authorization` when a token exists, but every map endpoint is free-tier by policy — `04-VALUE-PROP-AND-MONETIZATION.md` §3 requires the base layers stay open for UMKM equity (Locus Charter). Auth belongs to premium features only (`ROADMAP.md` §6.1); do not "tidy this up" by adding global route protection.
- **The data/logic/presentation split is a hard requirement, not a preference** (`ROADMAP.md` §1 — the pause between Fase 1 and 2 exists so visuals can be reworked freely). It is currently enforced by four layers, and changing a colour or a layout must never require touching the first three:
  - `lib/data/usePetaData.ts` — loads all four mock sources **once**, at the screen level. `MapCanvas` no longer fetches anything; it draws what props tell it to. Loading in both places meant the panel and the map could hold different copies of the same numbers.
  - `lib/data/dimensions.ts` — the `SLOTS` and `CATEGORIES` lists. Data keys (`pagi`/`siang`/`sore`/`malam`) are separate from screen labels (`06–09` …) and from the true counted range (`jam`, e.g. `16.00–18.59`). Don't duplicate these lists into a component; one mismatched label silently selects the wrong slot.
  - `lib/analytics/select.ts` — pure functions (no React, no MapLibre) that decide *which* number a given slot × category shows, plus `domainOf()` for the active scale. `metricFor()` never computes a derived figure — it only picks one that exists in the payload.
  - `lib/map/style.ts` — colours and sizes only. Since Fase 1.5 the gap scale follows the data, so `Domain` is passed **in** as an argument; the file defines the ramp, never the range.
- **`setFeatureState` must be re-applied on `sourcedata`, and that includes interaction state.** A GeoJSON source re-tiles whenever its data changes and drops all feature state with it. `MapCanvas` therefore writes the analytics values *and* `terpilih`/`hover` from a single `apply()` registered on `sourcedata`. An earlier version set `terpilih` from its own one-shot effect: the numbers came back after a re-tile but the selected ring silently vanished. Fase 2 hits the same hazard for a different reason (new vector tiles arriving on pan — ROADMAP 2.4).
- **Don't register map event listeners inside the effect that also sets `layersReady`.** That effect has `layersReady` both as a dependency and as an early-return guard, so it runs a second time the moment the flag flips: React tears down the old listeners first, then the guard returns before re-adding them. The map looks perfect and answers no clicks. Interaction handlers live in their own effect keyed on `layersReady`.
- **Project docs**: `DATA_CONTRACT.md` (frontend ⇄ backend agreement), `ROADMAP.md` (phased plan), and `USER_FLOW.md` (what a user can actually do, screen by screen — written in Obsidian flavour: YAML frontmatter, callouts, mermaid, and `[[wikilinks]]` to the other three docs) are committed. `USER_FLOW.md` deliberately separates working interactions from the intentionally-inert ones, so keep that split honest when editing it. `Proposal_IsiStasiun.pdf` and `BACKEND_TASK_DIVISION_3_PERSON.md` are gitignored — read them for context but never commit them.
- **Typed route props**: `app/layout.tsx` takes `LayoutProps<"/">` (see its `children` prop), a globally-available type Next.js 16 generates per-route from `.next/types` — not an import. Page components would use the equivalent `PageProps<"...">`. None of the 5 `page.tsx` files need it yet (no dynamic segments), but reach for `PageProps<"/route">` rather than hand-rolling a props type if one gains params/searchParams.
